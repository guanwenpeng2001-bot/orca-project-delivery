# Product Design

## Core principle

A design is a behavior contract, not a collection of visual adjectives.

## Workflow

1. Map the primary user journey and the user's entry and exit conditions.
2. Define information hierarchy, navigation, actions, and feedback.
3. Specify loading, empty, success, error, permission, interruption, recovery, and destructive states.
4. Reuse the existing design system, interaction language, and platform conventions.
5. Check keyboard, focus, screen-reader, contrast, motion, localization, and responsive implications where material.
6. Translate the design into observable acceptance criteria.

## Required output

- User-flow map
- Screen/component responsibilities
- State table
- Interaction and accessibility rules
- Content requirements
- UX acceptance criteria

## Rules

- Do not invent new screens without a requirement.
- Do not dictate internal implementation unless it affects behavior.
- Do not omit failure and recovery states.
- Do not replace project design conventions with generic trends.
